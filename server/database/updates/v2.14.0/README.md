# v2.14.0 升级说明

## 版本内容

admin 订单管理新增「拆单、合单、改价」三项能力：

1. **改价**：仅待付款（pending）且无活跃支付单的订单，可修改商品单价/运费/整单优惠；改价前自动关闭旧支付尝试并在锁内二次断言，杜绝支付回调金额不一致。
2. **拆单**：已支付（paid）未发货订单可按商品行整行迁移或数量拆分为子单；子单继承 paid 状态并通过 `payment_root_order_id` 扁平化指向持有支付记录的根订单，退款额度按「订单家族」聚合校验防止超退；merchant 配送子单事务后幂等补建配送单。
3. **合单**：同一用户多笔待付款订单（同配送方式）合并为最早一笔存活订单，其余订单以专用通道关闭（不回补库存、不退优惠券——商品行仍存活），优惠券改绑存活单。

所有操作写入 `order_adjust_logs` 审计流水（前后金额快照 + 操作人 + 原因），订单详情页可查看血缘关系与改价历史。

守护边界：秒杀/拼团订单禁止拆单与合单；虚拟商品订单禁止拆单；已开发票订单禁止拆单；拆单订单级禁止全拆。

## 数据库变更

- `order_orders`：新增 `parent_order_id` / `relation_type` / `payment_root_order_id` 三列与两个索引。
- `order_items`：新增 `split_from_item_id` 列与索引。
- 新表 `order_adjust_logs`（审计流水，append-only）。
- `permissions` 新增 333-335（order.split / order.merge / order.price-adjust），`menus` 新增 815-817 按钮，并授权超级管理员角色。

## 升级步骤

1. 备份数据库。
2. 执行 `update.sql`（脚本幂等，可重复执行）。
3. 管理员重新登录后台以刷新权限（或清除权限缓存）。

## 注意事项

- 存量订单 `payment_root_order_id` 为 NULL（自身即根），退款行为与升级前完全一致。
- 若使用自定义角色，需在「角色管理」中为相应角色勾选新增的三个权限。
